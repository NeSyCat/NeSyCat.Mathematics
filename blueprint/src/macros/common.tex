% Section numbering (C2-E2, single-SOT): both print.tex and web.tex load
% \documentclass{report}, whose top-level sectioning unit is \chapter, so
% \thesection defaults to \thechapter.\arabic{section} -- since this
% document never issues a \chapter, that rendered every top-level
% \section as "0.1", "0.2", etc. This library uses \section as its own
% top-level unit (no \chapter anywhere in content.tex), so \thesection is
% redefined here to plain arabic numbering, 1, 2, 3, ...; \thesubsection
% then falls out correctly from report's own
% \thesection.\arabic{subsection} definition. Lives here, once, so both
% engines (print.tex and web.tex each \input this file before
% \input{content}) inherit the identical fix -- no per-engine duplicate.
\renewcommand{\thesection}{\arabic{section}}

% The theorem-like environments defined below are those that appear by default
% in the dependency graph. See the README of leanblueprint if you need help to
% customize this.
%
% FINAL ENVIRONMENT INVENTORY (C2-E4a full Lean-kind sync, USER DECREE
% 2026-08-09, supersedes every earlier \newtheorem block in this file's
% history): the blueprint's environments are EXACTLY Lean's own
% declaration kinds --- def, class, instance, abbrev, lemma, theorem (+
% proof per the proof-presence law) --- rendered below as the LaTeX env
% names definition/class/instance/abbreviation/lemma/theorem/proof, with
% WRITTEN-OUT English heads: "Definition 3" (def-kind), "Class 5",
% "Instance 2", "Abbreviation 1" (abbrev-kind), "Lemma 7", "Theorem 4".
% `definition` keeps its spelled-out internal name rather than a bare
% `def` specifically to dodge a TeX-level clash: LaTeX's environment
% mechanism expands `\begin{def}`/`\end{def}` to `\def`/`\enddef`
% internally, colliding with TeX's own `\def` primitive --- naming the
% environment `definition` sidesteps that clash entirely while still
% being kind-restricted to Lean `def`/bare-`structure` declarations (see
% scripts/blueprint.sh's kind-check). `abbreviation` likewise keeps its
% spelled-out name (no clash risk, but consistent with `definition`).
% `class` and `instance` are brand-new environments introduced by this
% ticket, one-for-one with Lean's `class`/`instance` keywords.
% remark/proposition/corollary/example/conjecture are ABOLISHED (C2-E3 +
% C2-E4a) and have NO \newtheorem declaration at all here --- a stray
% occurrence in content.tex is a raw "Environment ... undefined" LaTeX
% error at build time, backstopped by scripts/blueprint.sh's
% CORRESPONDENCE section catching it mechanically as a named violation
% (not merely a build crash) whenever the gate runs. Re-kinding rule
% (from content.tex's own "Blueprint-to-Lean correspondence" paragraph):
% every environment's kind is fixed by its item's PRINCIPAL Lean
% declaration --- a class-kind declaration (BLat2Mon, the LatSRng family,
% DMStructure, the unit-bound mixins, ...) lives in a `class` env; an
% instance-kind declaration (a concrete carrier's witness) lives in an
% `instance` env; everything else with new mathematical content and no
% class/instance kind lives in `definition`; a former `example`
% environment either promotes to `instance` (if it witnesses a class,
% e.g.\ the library's three running lattice-semiring instances) or
% dissolves into plain narrative prose; a former `conjecture` promotes to
% `theorem` with a proof environment whose body is exactly the sentence
% "Open." and which never carries \leanok --- the open-theorem
% convention, replacing the old conjecture-never-has-a-proof rule now
% that conjecture no longer exists as a kind of its own.
%
% INDEPENDENT PER-KIND COUNTERS (USER DECREE 2026-08-09, C2-E4a
% supersedes the former shared `[theorem]`-argument mechanism below):
% each kind now numbers on its OWN counter (no `[theorem]` argument to
% any \newtheorem call), restarting at 1 and incrementing only within its
% own kind --- Lemma 1..n, Definition 1..m, Theorem 1..k, Class 1..j,
% etc., all independently; plain global per-kind numbering, not
% per-section (no `[section]`/`[chapter]` argument either). Cross-refs
% stay safe by house style: prose always names the kind before \ref
% (`Definition~\ref{...}`, never a bare `Item~\ref{...}`), so two
% different kinds sharing a bare number (e.g.\ a "Definition 3" and a
% "Theorem 3" coexisting) never reads as ambiguous.
%
% Typography grid (user decree, M4 addenda #1+#3, remapped onto the new
% kinds): ITALIC body for every definitional/claim environment ---
% definition, class, instance, abbreviation, lemma, theorem (amsthm's
% "plain" style: bold heading, italic body) --- and UPRIGHT body for
% proof (amsthm's own built-in environment, unaffected by
% \theoremstyle, never redeclared here). "plain" is amsthm's own default
% before any \theoremstyle call, but it is set explicitly here for
% clarity.
\theoremstyle{plain}
\newtheorem{definition}{Definition}
\newtheorem{class}{Class}
\newtheorem{instance}{Instance}
\newtheorem{abbreviation}{Abbreviation}
\newtheorem{lemma}{Lemma}
\newtheorem{theorem}{Theorem}

% ===== SHARED-MACRO IMPORT (single source of truth: NeSyCat.Logics/macros.sty) =====
% User decree: symbols shared with the NeSyCat papers (\seq, \seqop,
% \bind, \sem, \parr, and the domain-signature vocabulary
% \Rel/\Var/\Fun/\Conn/\inn/\out) are defined ONCE, centrally, in
% NeSyCat.Logics/macros.sty, and imported here rather than re-invented
% locally --- via a single import mechanism, identical on both engines
% (M4: the prior per-engine \usepackage-vs-local-\providecommand split
% is gone; see below for why it is no longer needed).
%
% Root cause of the earlier plasTeX crash on
% `\usepackage{../../../NeSyCat.Logics/macros}` (diagnosed by reading
% plasTeX 3.1's own source, then confirmed by direct reproduction
% against this venv's plasTeX): \usepackage's handler
% (plasTeX.Context.loadPackage/loadPythonPackage) does not go straight
% to a TeX-style file search. It first tries to import the package
% "name" as a Python module --- `import_module(plugin + '.Packages.' +
% module)` --- with `module` set to whatever raw string was passed to
% \usepackage, here the entire relative path
% `../../../NeSyCat.Logics/macros`, slashes and all. That import fails,
% and the surrounding `except` only swallows a `ModuleNotFoundError`
% when `module in str(msg)`; a path containing slashes and a dot is not
% a substring of Python's own "No module named ..." message, so the
% exception escapes uncaught instead of the code ever falling through
% to its later kpsewhich/LaTeX-package branch --- the crash. `\input`,
% by contrast, calls `tex.kpsewhich(name)` directly and never enters
% this Python-import machinery at all; reproduced directly that
% `\input{path/with/slashes/macros.sty}` loads cleanly under plasTeX
% with no engine-specific handling needed (kpsewhich treats a name
% containing a path separator as a literal filesystem path on both
% real kpsewhich and xelatex's kpathsea).
%
% Fix: `\input`, not `\usepackage`, identically on both engines below.
% The remaining engine split is solely about typesetting quality, not
% about the import itself: real xelatex additionally loads the real
% `stmaryrd`/`cmll` packages first, for their genuine \fatsemi/\parr
% glyphs (reproduced directly that asking plasTeX to load stmaryrd.sty
% as a generic, Python-less LaTeX package does not crash but does not
% work either --- it cannot process stmaryrd's
% `\DeclareSymbolFont`/`\DeclareMathSymbol` font machinery, so \fatsemi
% comes out genuinely undefined despite no reported error --- hence
% plasTeX never attempts it). On the web path, macros.sty's own
% `\providecommand`-guarded \fatsemi/\parr fallbacks (see macros.sty)
% take over automatically: the same central file degrading gracefully,
% not a second local definition of these symbols.
% `@` must stay catcode-letter across the \input below too, not just the
% engine check: unlike \usepackage, a bare \input does not itself flip
% `\makeatletter` around the loaded file, and macros.sty's own
% `\ProvidesPackage`/`\NeedsTeXFormat`/`\@ifpackageloaded` lines need `@`
% as a letter to parse at all (an emergency stop otherwise, reproduced
% directly while drafting this ticket) --- so \makeatother only closes
% once the \input has completed.
\makeatletter
\@ifundefined{XeTeXversion}{}{%
  \usepackage{stmaryrd}
  \IfFileExists{cmll.sty}{\usepackage{cmll}}{}
}
\input{../../../NeSyCat.Logics/macros.sty}
\makeatother
